> **一层网络刚刚算出的东西，是否必须全部立刻成为这一层的输出？**
>
> WR-Reserve 给出的选择是：把 FFN 的少量中间通道留作工作寄存器，供后面的层读取和改写。当前推荐版本采用 **Block AttnRes + 64 维工作状态**，在相同 AttnRes 底座上获得了额外收益：15.85M 模型三个初始化种子的独立分片 PPL，按平均 CE 换算下降 **4.38%**；34.38M 模型单种子下降 **2.84%**。100M 配置完成了预算与短时性能验收，长期训练质量尚待验证。

这篇文章记录的是一次从“给 Transformer 增加工作空间”到“重新分配 FFN 计算职责”的研究过程。它包含早期弱结果、结构推导、最终方案、实验协议、机制消融，以及接下来怎样验证更强的主张。本文中的实验数字来自 2026 年 9 月 8 日的本地记录；写作阶段重新核对了原始 JSON 与实现，没有重新运行模型训练。

最重要的定位先放在前面：**WR-Reserve 是一项有初步实证支持的工作寄存器模块。当前最佳版本仍然使用 AttnRes，并未建立一套已经优于 Hyper-Connections 或 AttnRes 的独立连接架构。**

# 1. 为什么还需要一种“工作空间”？

## 1.1 从残差中的结果，回到 FFN 内部的计算

在普通的残差 Transformer 中，一个 FFN 接收当前表示，展开到更宽的中间空间，再投影回模型宽度。以 SwiGLU 为例，忽略层编号：

$$
z=\operatorname{RMSNorm}(x),\qquad
h=\operatorname{SiLU}(W_gz)\odot W_uz,\qquad
f=Dh.
$$

其中 $x,z,f\in\mathbb R^d$，$h\in\mathbb R^m$，通常 $m>d$。主残差接收 $f$，后面的层继续在公开表示上工作。

这种设计非常有效，但它没有为“尚未准备好成为本层输出的内部特征”设置独立的存续通道。后层可以从公开表示中使用信息、重新分离信息，也可以重新计算某些特征。一个具体的研究问题因此出现：**能否用很小的状态，把一部分已经付过计算成本的内部结果传下去，让后层继续加工？**

这里的“寄存器”借用了计算机体系结构的直觉：计算单元旁边有一小块可以反复读写的临时状态。它并不意味着模型已经拥有离散地址、类型系统、变量名或精确赋值语义。

## 1.2 工作寄存器与公开路由分别解决什么

公开路由关注的是：**后面的层应当读取哪些已经公开的计算结果？** 工作寄存器关注的是：**当前计算的哪些部分先保留下来，留待后层继续处理？**

这两个问题有关联，却不相同。一个模型可以同时拥有可选择的公开历史与可改写的工作状态。前者保存可访问的结果，后者维护一份正在变化的材料。

## 1.3 “沿深度”是这个设计的关键限定

用 $l$ 表示网络层，$t$ 表示 token 位置，寄存器写成 $w_{l,t}\in\mathbb R^r$。它的直接递推是：

$$
w_{l+1,t}=F_l(w_{l,t},u_{l,t}),
$$

而不是 $w_{t+1}=F(w_t,x_t)$。后者属于沿序列时间演化的记忆设计；本文讨论的是前者。

<WorkingRegisterFigure name="depth-axis" alt="三个 token 的工作状态分别沿 FFN 深度传播，各 token 的读写并行进行。" />

*图 2：深度方向上的持续状态。图中只画寄存器路径，公开 Attention 仍然负责跨 token 的因果信息交互。这里的“第 3 个 FFN”是中间步骤示意，并不表示模型的末层也写状态。*

对一批长度为 $T$ 的序列，工作状态张量大小为 $B\times T\times r$。它不增加一个逐 token 的串行循环，不延长输入序列，也不额外运行一轮 Transformer。工作读写随网络层执行，所有 token 的对应操作可以一起计算。

一个 token 的寄存器仍然可能间接包含前文信息，因为它的公开输入已经经过因果 Attention；“没有直接跨 token 递推”不等于“内容完全独立于上下文”。

# 2. 一条没有立即成功的研究路线

## 2.1 最早的 FFN-WR：给内部特征增加一个出口

原始工作区方案让主输出与工作输出同时读取 FFN latent：

$$
f_l=D_lh_l,\qquad
w_{l+1}=w_l+E_lh_l.
$$

这个方案有清晰的动机：$E_l$ 可以捕捉 $D_l$ 没有传出去的方向。但它也增加了独立 writer 和后续读取成本。能访问额外特征，并不自动意味着这些特征值得保存。

早期约 100M 模型、seed 42、训练到 500,006,912 tokens 的最终验证结果并没有显示稳定收益：

| 早期方案 | 参数量 | 最终验证 CE ↓ | 相对普通基线的 ΔCE |
|---|---:|---:|---:|
| Transformer / WR-0 | 100.55M | 2.780906 | — |
| FFN 工作区，64 维 | 102.45M | 2.789233 | +0.008328 |
| FFN 工作区，256 维 | 108.15M | 2.784267 | +0.003361 |
| LIDM v1，112 维 | 103.30M | 2.779946 | −0.000960 |

*表 1：早期实验的日志审计摘要。ΔCE 来自未舍入数值，末位可能与表内六位小数相减不同。这是单种子历史实验；执行实现也存在差异，不构成严格的结构显著性结论。*

LIDM v1 的 CE 改善只相当于约 0.096% 的 PPL 下降。对于额外的参数与计算成本，这还不足以支撑强结论。

**这些旧实验不能与本文后面的短预算实验直接进行绝对 CE 排名。** 新一轮采用缓存 token 流，旧 streaming trainer 的打包细节不同；训练 tokens 也相差很大。旧结果的作用是解释设计转向，不是为最终模型制造一个不公平的低分参照。

## 2.2 LIDM：工作空间逐渐变成了历史档案

LIDM 的写入对象是已经生成的层增量：

$$
m_l=\operatorname{Encode}_l(\Delta_l).
$$

它让后层更容易访问某一层的贡献，而不必从混合残差中重新分离出来。不过，一旦写入源从内部 latent 变成公开 delta，研究问题也随之变化：它越来越像“如何组织历史结果的读取”。

早期诊断中，LIDM 已有非零读取，部分层的读取权重也相当集中。弱结果不能简单归因为“模型没有打开记忆”或“softmax 不够尖锐”。非零注入说明通路被使用，却没有回答它是否带来足够的额外任务价值。

因此，我们把问题从“能否保留更多历史槽位”收敛为：**能否明确分配一部分内部计算，使它负责跨层继续工作，而不只是重复保存已公开结果？**

## 2.3 零空间提供动机，但不能充当效果证明

以 $d=896,m=2400$ 为例，$D\in\mathbb R^{896\times2400}$ 至少具有 1504 维零空间。如果 $v\in\ker D$，那么：

$$
D(h+v)=Dh.
$$

两份不同的内部特征可以产生相同的主输出。因此，一个额外投影原则上能够保留主输出无法直接区分的变化。早期曾考虑强制：

$$
DE^\top=0.
$$

但“1504 维零空间”绝不是“丢失了 1504 维有用语义”。真实激活可能处在更低维的数据流形上，主输入仍可能携带相关信息，后层也可能以较低成本重新计算它。权重正交同样不保证数据上的统计独立或任务互补。

更直接的反证来自已有模型：在两个完成的 FFN-WR checkpoint 的第 0、4、8 层，writer 的零空间权重能量占比约为 40%–53%，但质量仍然没有明显提升。这个比例是**权重空间的 Frobenius 能量**，不是可用信息量；它至少说明“能读到零空间方向”本身还不够。

在线精确维护零空间还会面对另一笔成本：主投影不断更新，约束也必须更新。最终方案没有采用训练时 SVD、伪逆或额外正交损失，而是选择更简单、职责更明确的固定通道分区。

# 3. WR-Reserve：把 FFN 的少量通道留给后层

## 3.1 公开状态与工作状态

最终版本维护三类状态：

| 状态 | 内容 | 后续访问方式 |
|---|---|---|
| 公开来源集合 $\mathcal B$ | embedding 与已完成的 block sums | 子层通过深度注意力读取 |
| 当前公开累积量 $s$ | 当前 block 尚未提交的 Attention / FFN 输出之和 | 参与深度读取；边界处加入来源集合 |
| 工作状态 $w_l$ | 每 token 的 $r$ 维工作向量 | 下一层 FFN 通过 $R_l$ 读取并更新 |

公开侧采用 Block AttnRes。本地配置中，一个路由 block 包含 **4 个子层，即 2 个完整 Transformer 层**。对来源 $v_i$，子层 $j$ 使用自己的可学习伪查询 $\theta_j$：

$$
\alpha_{j,i}=\operatorname{softmax}_i
\left(\theta_j^\top\operatorname{RMSNorm}_j(v_i)\right),\qquad
u_j=\sum_i\alpha_{j,i}v_i.
$$

来源包括已经完成的公开 block 以及当前非空 partial sum；实现按先读取、再在边界提交 partial 的顺序执行。该机制已有公开的 [AttnRes 官方伪代码](https://github.com/MoonshotAI/Attention-Residuals)。工作寄存器沿用这一公开汇聚机制，不把它重新命名为自己的贡献。

Attention 从公开深度读取生成正常的因果 Attention 输出，再加入 $s$。接着，FFN 读取更新后的公开来源，得到 $u_l^F$，并开始下面的工作寄存器计算。

## 3.2 先读，再计算，再分别产生两种输出

记 $d$ 为模型宽度，$m$ 为 FFN 中间宽度，$r$ 为工作宽度。对一个有读写能力的内部层：

$$
z_l=\operatorname{RMSNorm}_l^F(u_l^F+R_lw_l),
\qquad R_l\in\mathbb R^{d\times r}.
$$

这里选择的是**把工作读取与公开输入先相加，再一起归一化**。两路原有投影的宽度保持不变：

$$
a_l=W_{g,l}z_l,\qquad b_l=W_{u,l}z_l,
\qquad W_{g,l},W_{u,l}\in\mathbb R^{m\times d}.
$$

将两个投影结果按相同坐标分成公开部分 $C$ 与工作部分 $W$：前 $m-r$ 个通道用于公开输出，后 $r$ 个通道用于工作更新。

公开部分仍然是 SwiGLU：

$$
f_l=D_l\left[\operatorname{SiLU}(a_l^C)\odot b_l^C\right],
\qquad D_l\in\mathbb R^{d\times(m-r)},
\qquad s\leftarrow s+f_l.
$$

工作部分直接生成逐坐标门和候选值：

$$
g_l=\sigma(a_l^W+\beta_l),\qquad
c_l=\tanh(b_l^W).
$$

最后更新工作状态：

$$
\boxed{w_{l+1}=(1-g_l)\odot w_l+g_l\odot c_l.}
$$

写入不再需要独立的 $m\times r$ writer 矩阵，因为候选值与更新门就来自原有 gate/up 投影的尾部通道。对于当前 100M 配置，非末层的 2400 个通道被分为 **2336 个公开通道 + 64 个工作通道**，工作部分占约 2.67%。

## 3.3 什么叫“本层私有”

“私有”在这里是计算图性质：本层公开 down projection 没有连接到这 $r$ 个通道。固定本层公开输入与旧 $w_l$，仅改变本层的私有 gate/up 参数，可以改变新工作状态，却不会直接改变本层公开 FFN 输出。

这个性质为“暂存”提供了结构定义，但并不意味着寄存器内容已经与公开表示在语义上完全分离。两部分仍然来自同一个 $z_l$，可能高度相关；旧工作状态已经通过 $R_lw_l$ 影响本层的两路投影，所以**旧状态可以影响当前公开输出，新写入则留待后续层使用**。

新状态 $w_{l+1}$ 不直接送入下一层 Attention。它先由下一层 FFN 读取，经过计算影响新的公开输出，再通过公开路径影响更后面的 Attention。最终 LM head 同样只读取公开深度汇聚结果，没有直接读取 $w$ 的旁路。

这也是与“将 hidden state 简单加宽”的差异：寄存器拥有特定的读取位置、写入来源和公开延迟，不能任意参与所有子层。

## 3.4 一段对应公式的伪代码

```python
# 概念伪代码：省略公开 AttnRes 来源管理、batch 维与诊断逻辑。
# u 是本层 FFN 的公开深度读取；w 是旧工作状态。
def reserve_ffn(u, w, layer):
    read = 0 if layer.is_first else layer.R(w)
    z = layer.norm(u + read)
    a, b = layer.gate_proj(z), layer.up_proj(z)

    public_width = layer.m if layer.is_last else layer.m - layer.r
    f = layer.down(silu(a[..., :public_width]) * b[..., :public_width])

    if layer.is_last:
        return f, w  # 最终 head 不直接使用 w；末层不再写入

    g = sigmoid(a[..., public_width:] + layer.update_bias)
    c = tanh(b[..., public_width:])
    next_w = (1 - g) * w + g * c
    return f, next_w
```

公开来源管理仍需要在外部完成：Attention 与 $f$ 进入当前 partial sum，工作状态不会追加为一个新的 AttnRes 历史槽位。

# 4. 预算为什么能对齐：省一个出口，支付一个入口

普通 SwiGLU 的矩阵参数为：

$$
\underbrace{dm+dm}_{\text{Gate / Up}}+
\underbrace{dm}_{\text{Down}}=3dm.
$$

WR-Reserve 的一个内部层则为：

$$
\underbrace{2dm}_{\text{Gate / Up}}+
\underbrace{d(m-r)}_{\text{公开 Down}}+
\underbrace{dr}_{\text{工作 Read}}=3dm.
$$

这个等式的意义很具体：少做 $r$ 个通道的公开输出投影，恰好支付读取 $r$ 维工作向量的投影。

## 4.1 首层与末层必须一起处理

不能只证明内部层等式就宣称全网络对齐。边界规则是：

- **首层**：$w_0=0$，没有读取矩阵；有私有写入，公开 down 仍缩小。
- **中间层**：读取旧状态，生成公开输出，再写入新状态。
- **末层**：仍读取旧状态，但不再写入；公开 FFN 恢复全部 $m$ 个通道。

因此，$L$ 层网络的总矩阵参数为：

$$
\underbrace{2Ldm}_{\text{Gate / Up}}
+\underbrace{(L-1)d(m-r)+dm}_{\text{公开 Down}}
+\underbrace{(L-1)dr}_{\text{工作 Read}}
=3Ldm.
$$

*图 3：全网络预算闭合。额外参数来自非末层的更新门偏置，共 $(L-1)r$ 个；公开 AttnRes 的成本同时存在于两侧基线中。*

| 配置 | 纯 AttnRes 参数量 | 加 WR-Reserve | 增量 |
|---|---:|---:|---:|
| $d=384,L=8,m=1024,r=64$ | 15,849,600 | 15,850,048 | 448 |
| $d=896,L=10,m=2400,r=64$ | 100,589,440 | 100,590,016 | 576 |

## 4.2 等矩阵预算不等于零成本

线性投影 MAC 数对齐，也不保证实际训练时间相同。逐元素 sigmoid、tanh、状态更新、张量读写以及矩阵形状都可能改变内核效率。训练还需要保存相应的反向中间量，不能把一个前向工作状态的大小当作全部训练显存增量。

以 $B=32,T=256,r=64$、FP32 为例，一份工作向量张量为：

$$
32\times256\times64\times4\ \text{bytes}=2\ \text{MiB}.
$$

这是单份状态的大小。实际峰值显存还受到 autograd、投影激活、编译器 buffer 与其他网络部分影响；后文报告的是实测 PyTorch 峰值已分配显存。

## 4.3 初始化并不是无损扩张

最终实现采用以下初始化：公共张量与相同 seed 的基线配对；非末层 down 保留前 $m-r$ 列，并乘 $\sqrt{m/(m-r)}$ 补偿初始化方差；$R_l$ 从零开始；私有 gate 投影行置零；$\beta_l=\log(1/3)$，于是初始更新门恰为 0.25；私有 up 保留正常初始化。

零初始化的读取矩阵不必导致通路永久关闭：只要旧工作状态非零，读取矩阵本身就可以获得任务梯度。随着读取打开，私有 writer 再通过后层获得任务梯度。

不过，公开 down 被截断和缩放，所以 WR-Reserve **不与原模型初始函数完全相同**，不能据此承诺已有 checkpoint 的无损转换。配对初始化减少实验差异，并没有消除结构与初始化方式的全部影响。

# 5. 这个门控状态具有哪些性质？

## 5.1 坐标有界，完整动力学仍需检查

因为 $g_l\in(0,1)^r$，$c_l\in(-1,1)^r$，并且 $w_0=0$，每一步都是旧值与候选值的逐坐标凸组合，所以在精确算术下：

$$
w_l\in[-1,1]^r.
$$

这防止寄存器坐标通过无约束加法一路累积，但它不是整个网络的稳定性定理。读取 $R_lw_l$ 仍受 $R_l$ 的尺度影响；门与候选本身也依赖旧状态。完整 Jacobian 中除了 $\operatorname{diag}(1-g_l)$，还有来自 $\partial g_l/\partial w_l$ 和 $\partial c_l/\partial w_l$ 的项，扰动仍可能放大。

## 5.2 沿轨迹展开，可以看到“保留寿命”

将递推展开，利用 $w_0=0$，可以写成：

$$
w_l=\sum_{i<l}
\left[g_i\odot\prod_{i<j<l}(1-g_j)\right]\odot c_i.
$$

每个候选值对后层的贡献，由写入时的门与之后的保留系数共同决定。不同坐标可以具有不同的保留长度，而且这种长度可以依赖输入内容。

如果暂时把一个坐标的门固定为 $g=0.25$，某次写入经过 $k$ 次后续更新后保留的系数为 $0.75^k$，半衰期约为 $\log(0.5)/\log(0.75)\approx2.41$ 次更新。**这只是固定门的解析示例**，不是训练后寄存器寿命的测量。真实模型的门会变化，候选也依赖已有状态，不能用这个展开式把整个网络深度直接并行化。

## 5.3 结构互补，不保证语义互补

在扩展特征 $[\operatorname{SiLU}(a^C)\odot b^C,\tanh(b^W)]$ 上，公开投影可以写为 $[D,0]$，工作选择为 $[0,I]$。两者的坐标支撑不重合，这给出了清晰的职责划分。

但它不是在训练后的完整 SwiGLU latent 上求出“真正有用的零空间”。固定分区保证的是接口隔离，不保证信息独立、最优压缩、语义草稿或程序变量。这样的主张必须由数据与干预建立。

还有一种需要避免的退化：如果两条状态只是被重新拆分，而所有后续计算始终只看到它们的某个固定线性和，那么“延迟提交”可能只是残差的变量重参数化。WR-Reserve 的不同读取位置、私有写入与非线性更新提供了不同结构，但结构不同本身仍不等于任务更优。

# 6. 实验协议：先选择，再复核，再用独立分片评估

本轮共完成 18 个架构筛选与复核 run，累计 335,544,320 个训练 tokens。累计稳定训练计时约 2298 秒，即 38.3 分钟；该数字不包含冷编译、评估、保存和分析，也不代表研究总耗时。

## 6.2 基线该怎样解释

本轮 HC2 与 Block AttnRes 都是匹配本地 backbone 的对照实现。HC2 采用论文 Appendix H 的动态映射与静态连接不衰减策略，最终取两条流的均值以配对本地初始化，没有完整复制原论文的输出缩放与大规模训练条件。

因此，下面的结果用于回答本地研究问题，不能写成“复现并击败原论文的大模型”。尤其应当把 **AttnRes 底座的收益**与**寄存器的增量收益**分开。

# 7. 质量结果：最关键的是相同底座上的额外收益

## 7.1 公开路由本身贡献很大

小模型、seed 42、相同训练预算，在独立分片上的结果为：

| 本地方案 | 独立分片 CE ↓ |
|---|---:|
| 普通 residual | 4.877355 |
| HC2 local | 4.710633 |
| Block AttnRes | 4.603468 |
| Block AttnRes + WR-Reserve | **4.562860** |

从普通 residual 到 AttnRes 的 CE 差约为 −0.273887；从 AttnRes 到加寄存器的差约为 −0.040608。二者不能合并后全部归功于 WR-Reserve。

这也是最终没有选择普通 residual 上独立 Reserve 作为默认方案的原因。在两个开发切片的均值上，普通 residual 的 CE 为 4.876225，Reserve-64 为 4.870734，只改善约 0.005491。公开结果如何被组织，仍然是重要的能力来源。

## 7.2 三个小模型配对，以及一个较大模型复核

<WorkingRegisterFigure name="quality" alt="独立分片上四组同底座配对的 CE 降低量，三个小模型种子和一个较大模型均改善。" />

*图 4：横轴为 baseline CE 减去 WR CE，越大越好；所有条形从零开始。斜线条表示不同规模与训练预算的较大复核，不能据此拟合 scaling law。没有绘制置信区间。*

| 模型 / seed | 纯 AttnRes CE | 加 WR-Reserve CE | ΔCE（WR − 基线） |
|---|---:|---:|---:|
| 15.85M / 42 | 4.603468 | 4.562860 | −0.040608 |
| 15.85M / 43 | 4.648525 | 4.592109 | −0.056416 |
| 15.85M / 44 | 4.610750 | 4.573267 | −0.037482 |
| 34.38M / 42 | 3.788360 | 3.759523 | −0.028837 |

CE 使用自然对数，以 nats/token 计。若 $\operatorname{PPL}=\exp(\operatorname{CE})$，相对 PPL 变化为：

$$
\frac{\operatorname{PPL}_{WR}}{\operatorname{PPL}_{base}}-1
=\exp(\operatorname{CE}_{WR}-\operatorname{CE}_{base})-1.
$$

小模型三种子的平均 ΔCE 为 −0.044836，先对 CE 求均值、再换算 PPL 比值得到约 **−4.3845%**。这个口径对应几何平均 PPL 的比值，不是把绝对 PPL 相减，也不是错误地把 CE 的百分比当成 PPL 百分比。较大模型按同样公式得到 **−2.8425%**。

同一底座上的四组配对均改善，是当前最值得保留的结果。但小模型只有三个初始化种子，且 seed 42 参与过选择；较大模型只有一个种子。它们支持有限预算下的正向信号，不能证明所有规模或充分收敛之后都保持同样优势。模型规模与训练预算同时改变，也无法从两个数值推导收益随规模缩放的规律。

## 7.3 重放检查与统计证据不是一回事

最终评估前，实验重新加载 10 个 checkpoint，并重放此前的开发切片；CE 与已有记录的绝对差全部为 0。它说明本轮保存的权重与当前评估实现能够复现已有数值。

这并不是重新训练 10 次的结果，更不等价于跨硬件、跨实现独立复现。精确重放提高了记录可信度，统计泛化仍由更广的数据、种子与训练条件决定。

# 8. 消融告诉我们：哪些直觉需要保留，哪些需要放弃

## 8.1 只用寄存器调 gate，没有成为最佳方案

早期直觉是：工作状态也许应该只控制特征选择，不直接进入完整 FFN 输入。因此测试了 gate-only 读取。实验没有支持把它作为默认方案。

<WorkingRegisterFigure name="ablation" alt="开发集上的从头训练消融。完整读取与 carry 的组合改善最大，gate-only 接近纯 AttnRes。" />

*图 5：相同 AttnRes 底座、seed 42、相同训练预算下的开发结果。纯 AttnRes 为零点，数值是相对它的 CE 降低量。这些开发数据参与选型，不与图 4 混称为独立测试。*

| 从头训练的设计 | 两个开发切片平均 CE ↓ | 相对完整方案的 CE 增加 |
|---|---:|---:|
| 完整 WR-Reserve | **4.572082** | — |
| 去掉 carry：$w_{l+1}=g_l\odot c_l$ | 4.586177 | +0.014095 |
| 工作读取只进入 gate 分支 | 4.610858 | +0.038777 |
| 纯 Block AttnRes | 4.614679 | +0.042597 |

需要准确理解“去掉 carry”：这个实现仍然保留门控候选 $g_l\odot c_l$，并非强制 $g=1$ 的无条件覆盖；它也仍可能通过候选对旧状态的依赖传递信息。该消融隔离的是显式 $(1-g_l)\odot w_l$ 保留路径的价值。

gate-only 与完整读取还改变了归一化位置及 up 分支可见的信息。因此，它支持当前组合选择更好，却不能单独证明“up 分支读取”或“归一化位置”中的哪一项贡献了多少。若要解释原因，需要进一步正交消融。

## 8.2 关闭或打乱状态，模型确实会受损

在独立分片上，小模型关闭寄存器后，CE 增加约 0.248–0.308；跨 batch 打乱工作读取后，CE 增加约 0.389–0.478。较大模型关闭工作状态也损伤预测。这支持模型实际利用了这条通路，且正确的状态内容具有作用。

但干预损伤远大于从头训练的架构增益，并不矛盾。模型训练时已经适应了特定的联合输入分布；突然删除或替换状态，会打破这种协同。干预损伤不能直接解释为“寄存器贡献了等量的独立能力”。

从头训练的 carry 消融和推理时内容干预回答的是不同问题：前者比较学习系统能否适应缺少某种结构，后者检验已经训练好的系统是否依赖当前状态。二者结合比单独观察非零门更有说服力，但还不足以证明变量绑定或人类式工作记忆。

## 8.3 负结果限制了故事的范围

普通 residual 底座上的 Reserve-32、gate-only 和 overwrite 在本轮开发结果中都没有超过普通基线。原始 FFN-WR 在小实验中与 Reserve-64 的质量接近，但需要更多参数与时间。扩大状态、改写门控、增加历史来源并不自动带来更好的资源利用。

因此，当前结论集中在一个窄而明确的组合：**64 维私有通道、归一化前完整读取、显式跨层保留，以及相同的 Block AttnRes 公开底座。**

# 9. 效率：训练目标、吞吐与端到端时间要分开

## 9.1 少用 tokens 达到一个已记录的开发指标

三个小模型种子中，WR-Reserve 在第 3584 步的开发 CE，均低于对应 AttnRes 在第 4096 步的结果。两者相差 512 步，即 **12.5% 的训练 tokens**。

| seed | 基线至 4096 步的窗口时间 | WR 至 3584 步的窗口时间 | 时间减少 |
|---|---:|---:|---:|
| 42 | 104.27 s | 92.07 s | 11.70% |
| 43 | 101.19 s | 89.09 s | 11.95% |
| 44 | 98.63 s | 91.52 s | 7.21% |

这些时间从日志中的 step/throughput 窗口重建，不含冷编译、评估和日志开销。它们说明，在这些离散开发检查点上，寄存器用更少训练 tokens 达到了更好指标；没有进行盲测 test 的完整 time-to-quality 曲线测量，不能承诺所有目标 loss 下固定加速。

较大模型在相同完整训练 tokens 下，稳定训练时间由 380.75 秒增至 387.86 秒，增加约 1.87%。它更好地说明两件可以同时成立的事：单步略有成本，有限训练预算下的质量更好。

## 9.2 100M 的实际吞吐与显存

*图 6：RTX 5070 Ti 上的完整 optimizer-step 短基准。固定有效 batch 为 64，每步 16,384 tokens；预热 2 步后测量 8 步。绝对吞吐的横轴从零开始，微小差异用精确数值解释。*

| 模型 | Micro-batch × 累积次数 | 稳定 tokens/s ↑ | 峰值已分配显存 |
|---|---:|---:|---:|
| AttnRes + WR | 8 × 8 | 37,392 | 3.28 GiB |
| AttnRes + WR | 16 × 4 | 38,542 | 5.00 GiB |

## 9.3 工程验收覆盖到哪里

原实验记录包含公共测试 75 项通过、4 项因旧参考文件缺失而跳过，以及训练到 step 2、保存、恢复到 step 4、公共 evaluator 重评等入口检查。这些验证说明研究实现能接入原有训练链路，不是长期模型质量的替代证据。

当前还不能据此宣称生产 KV cache 已完整实现；早期 CPU harness 的缓存等价检查只是数学参考。局部 depth-control 实现也显式不支持 activation checkpointing。长上下文、低精度、更大 batch、实际增量解码与多卡训练的行为，仍需分别验证。

# 10. 与已有工作的关系：贡献应当落在具体接口上

工作寄存器的吸引力并不来自一个全新的 sigmoid 或 EMA。跨深度状态、可学习残差连接与门控记忆都有重要先例。下面按设计对象区分，而不把不同论文排成单一优劣榜。

| 方向 | 主要设计对象 | 与 WR-Reserve 的关系 |
|---|---|---|
| [Hyper-Connections](https://arxiv.org/abs/2409.19606) | 层间连接及表示流的动态组织 | 研究宏观信息流；本轮只做了本地 HC2 对照 |
| [DenseFormer](https://arxiv.org/abs/2402.02622) | 当前与历史表示的深度加权平均 | 关注已产生表示的复用 |
| [Attention Residuals](https://github.com/MoonshotAI/Attention-Residuals) | 对早期层 / block 表示的内容相关读取 | 当前组合的公开路由底座，收益单独计量 |
| [Depth-Wise LSTM Transformer](https://aclanthology.org/2024.lrec-main.1231/) | 沿深度的 LSTM 连接 | 表明深度方向的门控记忆已有先例 |
| [Deep Delta Learning](https://arxiv.org/abs/2601.00417) | 读取残差状态、比较目标、写回门控修正 | 读写与替换不是本文独有概念 |
| [Vision Transformers Need Registers](https://arxiv.org/abs/2309.16588) | 为视觉 Transformer 增加内部计算 token | “寄存器”的相关先例，但本文不增加序列 token |
| 本文 WR-Reserve | 在 FFN 矩阵预算内划分公开与工作通道 | 通过缩小公开 down 支付后层 read，不另加 writer |

WR-Reserve 最值得检验的主张由三部分组成：**部分 FFN 通道不即时公开；它们生成可改写的跨层状态；读写预算通过原投影重新分配而闭合。** 在本轮实验中，这个组合能在已有强公开路由之上获得额外收益。

这样的定位比“首次让 Transformer 拥有工作记忆”更精确，也更容易被复现或推翻。现有实验尚未直接比较 DDL 的同预算实现，没有覆盖更广的 HC 变体，也没有进行全面文献优先权证明。

# 11. 分析与展望：怎样把正向信号变成更强证据

## 11.1 为什么可能有效？目前有三种可检验解释

**第一，内部特征的跨层复用。** 预留通道让某些中间计算无需先投影到公开输出，再由后层恢复。若这是真正原因，那么工作状态应能降低后层重新计算特定信息的成本。可以用等算力预测器，比较从公开状态与公开状态加工作状态预测后续激活的效果，且必须保留公开输入这个强对照。

**第二，明确的计算分工。** 固定分区可能使优化更容易：部分通道负责现在的输出，部分通道负责后层所需的材料。若这一解释成立，那么即使没有很长的保持跨度，短程寄存器也可能有效；不同层、不同宽度的工作分配应该表现出规律。

**第三，公开路由与工作更新互补。** AttnRes 使公开结果更容易被选择，寄存器负责维护尚未公开的状态。当前组合的增益与这一解释一致，但还不能因果证明“强公开路由促成了私有状态价值”。需要多底座、多种子、匹配成本的实验矩阵，避免只在一个成功组合上构建叙事。

这三种解释也可能共同发生。通路带来的优化或初始化变化同样可能贡献收益，不能把所有改善预先归因于“记住了更多内容”。

## 11.2 更有价值的下一轮实验

| 待验证问题 | 建议实验 | 什么结果会削弱当前解释 |
|---|---|---|
| 收益是否经得起充分训练？ | 100M 配对长训练，多初始化与数据顺序种子 | 早期优势消失，或等时间质量更差 |
| 是否只适用于当前语料？ | 多语、代码、不同 tokenizer 与上下文长度 | 换分布后系统性退化 |
| 保存是否比重新计算划算？ | 等参数、等 MAC、等 wall-clock 的 FFN / 小分支控制 | 同成本重计算达到相同或更好效果 |
| 状态到底跨了多少层？ | 层级置零、保留窗口限制、门轨迹与小幅范数匹配干预 | 只依赖最新一层，较长 carry 无稳定价值 |
| 固定 64 维是否合理？ | 多种子宽度扫描，联合报告质量、吞吐与显存 | 更小状态等效，或 64 维选择高度偶然 |
| 能否形成可复用的变量状态？ | 需要绑定、重绑定、覆盖的受控任务与分布外测试 | 仅在训练模板上有效，状态不能稳定对应任务变量 |
| 是否必须依赖 AttnRes？ | 在 residual、HC、其他路由上加入同样分区 | 优势只出现在一个特定配置 |

重点不应是尽快给寄存器增加地址头、多槽位或辅助损失。更有价值的是先定位：**哪些特征值得留、应当保留多久、保存它们能否节省后续计算。**

## 11.3 一个值得认真考虑的资源取舍

工作宽度越大，非末层即时公开容量 $m-r$ 就越小。寄存器不是免费容量，而是在固定预算内把部分能力从“现在输出”转给“以后使用”。

这可能产生随深度变化的最佳分配：早层需要更长的潜在使用周期，末层则更需要直接输出。当前实现只处理了首末边界，没有验证层间非均匀的 $r_l$。若允许每层写入宽度 $r_l$、下一层读取同一宽度，依然可以研究全网络预算配对；但状态维度转换和坐标约定会引入新的复杂性，必须与简单的固定 64 维方案比较。

类似地，当前工作状态每次 forward 重新建立。把它改成跨 token 持久状态，会改变因果图、缓存语义、并行方式与训练协议，应作为另一项设计重新评估，不能从本轮结果直接外推长上下文记忆能力。

## 11.4 从模块走向架构，需要更强的判断标准

如果目标是一个可以独立替代 HC 或 AttnRes 的连接原语，那么仅证明“给 AttnRes 加上这个模块更好”是不够的。独立方案需要同时解释公开信息如何传播、私有状态如何更新、梯度如何跨深度传递，以及在相同预算下为什么更值得使用。

当前这一步的价值在于，它把“工作空间”变成了明确的结构与实验对象：输入从哪里来，状态写到哪里，哪些通道不能直接输出，下一层什么时候可以使用，以及为此付出了多少成本。这些问题现在都能落到公式、代码和对照实验上。

**让一部分计算晚一点公开，是一种值得继续研究的资源分配方式。** 它是否会成为通用架构原则，要由更充分的训练、机制实验和系统测量决定。
